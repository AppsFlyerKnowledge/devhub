## Версия 7.0.1

#### Новые возможности

- Добавлена коллекция хэшей PII для совместного использования через `setUserEmail`, `setUserPhone`, `setUserFirstName`, `setUserLastName`, `setUserFbLoginId`.

#### Измененные функции

- Удалены API `setUserEmails` и `setPhoneNumber` — полное удаление, а не устаревание. Вместо этого используйте `setUserEmail` и `setUserPhone`.

#### Техническое обновление

- Подключено `targetSdkVersion` к 36.

## Версия 6.18.1

- Исправлена проблема в коннекторе Purchase Connector, где некорректно кэшировались проверки покупки, которые не удалось отправить из-за сбоев подключения к сети.

## Версия 6.18.0

- Удалить код песочницы Google из SDK

#### Техническое обновление

## Версия 6.17.1

#### Новые возможности

- Добавлен Google Play Integrity API в качестве непосредственной зависимости SDK для активации проверки целостности устройства через службы Google Play.
  Примечание: Если ваше приложение распространяется за пределами Google Play Store, вы можете безопасно исключить эту зависимость, следуя инструкциям [here](https://dev.appsflyer.com/hc/docs/install-android-sdk#google-play-integrity-api).

- Обновлен API validateAndLogInAppPurchase API. В `AFPurchaseDetails`, добавлен обязательный параметр `AFPurchaseType` и удалены параметры `revenue` и `currency`.

## Версия 6.16.1

#### Измененные функции

- Обновлено API для отправки данных с согласия DMA вручную на AppsFlyer.
  Эти изменения включают:
  - Новый конструктор для генерации объекта AppsFlyerConent. Все параметры конструктора являются необязательными.
  - Новый конструктор содержит новый параметр флага - "ad_storage", который указывает, дает ли пользователь разрешение на хранение и доступ к информации на устройстве.
    See developer guide [here](https://dev.appsflyer.com/hc/docs/android-send-consent-for-dma-compliance#manually-collect-consent-data).

## Версия 6.15.0

Эта версия представляет важные обновления зависимостей, которые влияют на коннектор покупки и коннектор AdRevenue Connector для Android.

- Приложения, использующие коннектор AdRevenue и обновляющиеся до SDK v6.15.0 (и выше), должны удалить коннектор AdRevenue и перейти на SDK API. For more details, see [here](https://dev.appsflyer.com/hc/docs/ad-revenue-1).

- Приложения, использующие Connector и обновившиеся до SDK v6.15.0 (и выше), должны использовать Purchase Connector v2.1.0 (и выше)

#### Новые возможности

- Добавлен метод logAdRevenue для отправки данных о доходах рекламе на AppsFlyer.
  Примечание: Начиная с этой версии, коннектор Adenue больше не должен использоваться.
  For more details, see [here](https://dev.appsflyer.com/hc/docs/ad-revenue-1).

#### Измененные функции

- Обновлены правила резервного копирования SDK в соответствии с изменениями в Android 12 (dataExtractionRules).
  Дополнительную информацию см. в разделе [here](https://dev.appsflyer.com/hc/docs/install-android-sdk#merge-backup-rules-in-android-12-and-above)

#### Исправления ошибок

- Исправлена проблема с подключением покупки не обнаружить все покупки, сделанные приложением.
  Эта версия совместима с Purchase Connector v2.1.0.

## Версия 6.14.0

#### Новые возможности

- Добавлен новый API `validateAndLogInAppPurchase` для обеспечения проверки покупки в приложении и сообщения о покупке AppsFlyer.
  Этот API изначально выпущен как закрытая бета-версия и требует активации перед использованием.
  После официального выпуска новый API заменит старый API [validateAndLogInAppPurchase](https://dev.appsflyer.com/hc/docs/in-app-events-android#the-validateandloginapppurchase-method) API.

- Обновлена интеграция с Huawei Referrer В рамках новой интеграции, приложения, опубликованные на Huawei AppGallery и хотели бы использовать реферер Huawei нужно добавить новую зависимость. Узнайте больше об этом [here](https://dev.appsflyer.com/hc/docs/install-android-sdk#huawei-install-referrer).
