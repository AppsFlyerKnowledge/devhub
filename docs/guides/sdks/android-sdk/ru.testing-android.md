## Устранение проблем интеграции с Android SDK

-------------------------------------------

### Установка всегда приписывается органическим

**Сценарии**  
Вы тестируете атрибут по ссылкам атрибутов. Вы реализовали обработчик конверсий SDK, но журнал всегда показывает, что установка является органичной. Кроме того, в приборной панели не зафиксировано ни одной неорганической установки.

**Возможные причины**

1. Ваш ключ dev неверный - если вы указали неверный ключ dev, то установка не может быть присвоена.
2. Неверная ссылка атрибута. Смотрите наше [руководство по атрибуционным ссылкам](https://support.appsflyer.com/hc/en-us/articles/207447163).
3. Убедитесь, что устройство, на котором вы тестируете, зарегистрировано.
4. Неправильный канал определен в манифесте

### Установка не обнаружена или объявлена

**Сценарий**  
Вы тестируете атрибут, но журнал не показывает никаких данных об установке, таких как тип, запуск и т.д.

**Возможные причины**

1. Убедитесь, что в классе `Application` вызываются методы `start` и `init`.
2. Убедитесь, что устройство, на котором вы тестируете, зарегистрировано.

### Я получаю 404 при установке или записи событий

**Сценарий**  
Вы тестируете события в приложении, чтобы убедиться, что они назначены правильным источником медиафайлов. Тем не менее, журнал показывает ответ 404 как для установки, так и при отправке событий в приложении. На панели инструментов не отображаются ни установки, ни внутри-приложения.

**Возможные причины**  
Ответ 404 означает, что идентификатор приложения неверен. Убедитесь, что идентификатор приложения в параметре `applicationId` в файле `build.gradle` совпадает с идентификатором в панели управления.

### Выручка не зарегистрирована должным образом

**Сценарии**  
Вы тестируете события в приложении с доходом. События появляются на панели управления, но доход не записан

**Возможные причины**  
Параметр дохода некорректен. Не форматируйте значение дохода каким-либо образом. Оно не должно содержать разделителей запятой, валютных знаков или текста. Доходное событие должно быть похоже на 1234.56.

### Журнал показывает "AppsFlyer's SDK не может отправлять какие-либо события без предоставления devkey" при тестировании событий в приложении

**Сценарий**  
Вы пытаетесь увидеть события в приложении. Когда вы запускаете события, журнал показывает только "AppsFlyer's SDK не может отправлять какие-либо события без предоставления DevKey".

**Возможные причины**  
Вы вызываете метод `start` без передачи ключа dev в качестве параметра. Передать ключ dev методу.

### Журнал показывает «пока не отправляет данные, ожидают dev ключ» в журнале, когда я тестирую события в приложении

**Сценарий**  
Вы пытаетесь протестировать события в приложении. Когда вы запускаете события, журнал только показывает «Не посылать данные», ожидая dev ключ».

**Возможные причины**  
Вы называете `init` и передаете ключ dev в качестве пустой строки. Передать ключ dev методу.

### Я получаю ответ 400, когда я тестирую в приложении

**Сценарий**  
Вы пытаетесь протестировать события в приложении. Когда вы запускаете события, вы видите ошибку 400 в журналах.

**Possible reasons**  
This might indicate an issue with the dev key. Убедитесь, что ключ dev верный. Также, убедитесь, что ключ dev содержит только буквенно-цифровые символы.

### Журнал показывает «предупреждение: нет сервисов Google Play»

**Сценарий**  
logcat показывает предупреждающее сообщение «ВНИМАНИЕ: отсутствует Google Play Services».

**Возможные причины**  
В приложении отсутствуют зависимости Google Play Services. Это может помешать SDK собирать GAID, что может вызвать проблемы с атрибуцией.

Добавьте следующие зависимости в файл `build.gradle` уровня app:

```groovy
реализация 'com.google.android.gms:play-services-base:<current-version>'
реализация 'com.google.android.gms:play-services-ads-identifier:<current-version>
```

### Я получаю ответ 403 на установку или запись событий

**Сценарии**  
Вы пытаетесь протестировать установку и другие события преобразования в журнале. Когда вы запускаете эти события, вы видите ответ 403 (запрещен) в журналах.

**Возможные причины**  
Это может быть потому, что у вас есть пакет нуля, который не включает данные атрибуции; только данные по кликам и впечатлениям. Чтобы начать получать данные атрибутов, ознакомьтесь с [различными пакетами AppsFler](https://www.appsflyer.com/pricing/) и обновитесь по мере необходимости.Вы также можете связаться с нашей командой по работе с клиентами по адресу [hello@appsflyer.com](mailto:hello@appsflyer.com), если у вас есть вопросы о наших пакетах.

### Моё SDK соединение с AppsFlyer защищено TLS 1.0 или 1.1

Для обеспечения безопасности соединения с AppsFlyer TLS 1.2 или 1. и не на более низких версиях TLS используйте конечную точку `appsflyersdk.com` без префикса. Вызовите функцию [setHost](https://dev.appsflyer.com/hc/docs/android-sdk-reference-appsflyerlib#sethost) следующим образом: `setHost("","[appsflyersdk.com](http://appsflyersdk.com/)")`

## Создание приложения для отладки Android

-----------------------------

<span class="annotation-optional">Опциональная</span>  
Вы можете использовать варианты сборки Android Studio для настройки легкого в использовании [debug app](doc:integration-testing#debug-apps) в целях тестирования.

Все тесты могут быть выполнены как для производственных, так и для отладочных приложений.

**Шаг 1: Настройте Gradle `debug` сборки**  
На вашем уровне `build. файл `debug`[build type](https://developer.android.com/studio/build/build-variants#build-types) и установите`applicationIdSuffix`на имя тестового приложения (в данном случае`.debug\`).

```groovy
android {
    // ...
    buildTypes {
        // Предотвращает ошибку подписи при построении production app
        release {
            signingConfig signingConfigs. ebug
        } 
        debug {
            applicationIdSuffix ". ebug"
        }
    }
}
```

**Шаг 2: Добавьте новое приложение к AppsFlyer**  
Используйте полученное имя пакета в качестве ID приложения при [добавлении приложения на панели AppsFler](https://support.appsflyer.com/hc/en-us/articles/207377436), или попросите члена команды с доступом к панели управления добавить ее.

Например, если у вас есть приложение с именем пакета `com.your. Вы используете вышеуказанную конфигурацию Gradle, имя тестового приложения будет `com.your.app.debug\`. Передайте это имя как ID приложения при добавлении приложения в AppsFlyer.
