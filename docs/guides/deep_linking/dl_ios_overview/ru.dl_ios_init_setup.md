**На взгляд**: первоначальная настройка приложения позволяет маркетологу создать ссылки, которые отправляют существующие пользователи приложения непосредственно в приложение. Первоначальная настройка также является обязательным условием глубокой связи и отсрочки глубокой связи.

## Методы открытия приложения

Существует два метода открытия приложения, которые должны быть реализованы для покрытия всей вашей пользовательской базы. Используемый метод зависит от версии мобильной платформы.

Эти два метода и инструкции по их применению подробно описаны в следующих разделах.

| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Универсальные ссылки** | Открывает мобильное приложение по умолчанию. Универсальные ссылки используют формат обычных веб-ссылок (например, https://yourbrand.onelink.me или https://www.yourbrand.com) | iOS 9 и выше                                                                   | <ol><li>[Получить идентификатор и идентификатор пакета приложения.](#getting-the-app-bundle-id-and-prefix-id)</li><li> [Включить связанные домены.](#enabling-associated-domains)</li></ol> |

## Процедуры для универсальных ссылок iOS

### Получение ID пакета приложений и ID префикса

1. Войдите в учетную запись разработчика Apple.
2. В меню слева выберите **Сертификаты, Идентификаторы и Профили**.
3. Под **Идентификаторами** выберите **App IDs**.
4. Нажмите на соответствующее приложение.
5. Скопируйте ID префикса и ID пакета приложений.
6. Дать ID префикса и идентификатор набора приложений вашему маркету.
   Маркетер будет использовать его в панели управления AppsFlyer для регистрации приложения.
   ![certs_apple_info!](https://files.readme.io/6b67004-certs_apple_info.png "certs_apple_info")

### Включение связанных доменов

**Чтобы поддержать связанные домены в вашем приложении**:

Следуйте инструкциям по iOS [чтобы добавить связанные домены в ваше приложение](https://developer.apple.com/documentation/xcode/supporting-associated-domains#Add-the-associated-domains-entitlement-to-your-app).

### Настройка мобильных приложений для регистрации утвержденных доменов

Настройка мобильных приложений для регистрации утвержденных доменов происходит внутри Xcode. Он требует поддомен OneLink, который генерируется вашим маркером.

**Для настройки мобильных приложений для регистрации одобренных доменов**:

1. Получите поддомен OneLink от вашего маркета.
2. В Xcode, нажмите на ваш проект.
3. Кликните на цель проекта (смотрите последовательный скриншот).
4. Переключиться на вкладку **Capabilities**.
5. Включите **Связанный домен**.
6. Добавьте поддомен, который вы получили от вашего маркета.
   Формат `applinks:subdomain.onelink.me`.

![xcode-associated-domains!](https://files.readme.io/ed37397-xcode-associated-domains.png "xcode-associated-domains")

> 📘
> To associate a domain with your app, you need to have the associated domain file on your domain and the appropriate entitlement in your app. После того, как [перенаправить логику для существующих пользователей приложения](https://support.appsflyer.com/hc/en-us/articles/207032246-OneLink-templates#add-redirection-logic-for-existing-app-users) на конфигурацию шаблона OneLink, AppsFlyer содержит файл apple-app-site-association .
> Когда пользователь установит ваше приложение, система пытается загрузить файл домена и проверить домены в вашем `Associated Domains Entitlement`.

### Ограничения по Universal Link

#### Открытие приложений из браузеров

Универсальные ссылки работают только при нажатии на них. Например, при нажатии на ссылку в веб-странице или электронной почте. Вставка ссылки в адресную строку браузера не является глубокой ссылкой в приложение.

#### Поддомен OneLink

В то время как поддомен OneLink может быть изменен в любое время, он вызывает все существующие URL-адреса OneLink, используя оригинальный поддомен для остановки работы.

#### OneLink в социальных приложениях

Не все приложения, включая социальные сети, полностью поддерживают универсальные ссылки. Подробнее см. [это руководство](https://support.appsflyer.com/hc/en-us/articles/207032246-OneLink-Basic-Setup-Guide#partners-onelink-social-apps).

#### Прочие ограничения и вопросы

Также могут быть и другие ограничения с универсальными ссылками. Посетите [OneLink](https://support.appsflyer.com/hc/en-us/articles/360014821438) для получения более подробной информации.

## Процедуры схемы URI

Схема URI - это URL, который ведет пользователей непосредственно к мобильному приложению.

Когда пользователь приложения вводит схему URI в адресную строку браузера, или щёлкните по ссылке, основанной на схеме URI, запускается приложение и пользователь глубоко связан.

Всякий раз, когда Universal Link не удается открыть приложение, схема URI может быть использована как резервная копия для открытия приложения.

### Решение по схеме URI

**Определить схему URI:**

1. Связаться с продавцом.
2. Выберите схему URI. Например: `yourappname://`

> 📘
>
> - Используйте схему URI, которая является как можно более уникальной для вашего приложения и бренда, чтобы избежать случайного дублирования с другими приложениями в экосистеме. Перекрытие с другими приложениями является неотъемлемой проблемой в характере протокола схемы URI.
> - Схема URI не должна начинаться с _http_ или _https_.
> - Схема URI должна быть аналогичным образом определена на Android и iOS.

3. Отправить схему URI маркеру, например `afshopapp://mainactivity`.

### Adding URI scheme

**Чтобы добавить схему URI:**

1. В Xcode откройте файл информационного списка приложений.
2. Добавьте запись **типа URL**.
3. Разверните **тип URL** и **пункт 0** строк.
4. Добавьте уникальный идентификатор для приложения для идентификатора URL-адреса в качестве значения.
   Лучше всего выбрать уникальный идентификатор, который вряд ли будет использоваться другими приложениями.
5. Щелкните правой кнопкой мыши **Идентификатор URL** и выберите **Добавить Row** > **URI Схемы**.
6. Установил **пункт 0** своей уникальной схемой.

![info_list_uri_schemes!](https://files.readme.io/569ae8d-info_list_uri_schemes.png "info_list_uri_schemes")

### Требования:

Установлено устройство iOS с приложением. Убедитесь, что это исходный код приложения и версия, где вы внесли изменения и реализовали Универсальные ссылки и схемы URI.

### Проверка схемы URI:

1. Свяжитесь с маркетом и получите пользовательскую ссылку, которую они создали.
2. Отправьте короткий или длинный URL-адрес, который Маркетер предоставляет вам на ваш телефон. Вы можете:
   - Сканируйте QR-код с помощью камеры телефона или приложения QR-сканера.
   - Отправьте по электронной почте или WhatsApp самостоятельно ссылку и откройте ее на своем телефоне.
3. Нажмите ссылку на вашем мобильном устройстве. Приложение должно быть открыто на домашнем экране.

Если ссылка не открывает приложение, добавьте параметр `af_force_deeplink=true` к пользовательской ссылки атрибуции. Например:

```text
https://demo.onelink.me/1aBC/123ab45c?af_force_deeplink=true
```

### Ограничения схемы URI

Ни Apple, ни Google не содержат уникального имени для пользовательских схем. Выберите имя схемы, уникальное для вашего бренда, чтобы избежать конфликтов схем в разных приложениях. Хорошим названием схемы может быть ваш идентификатор пакета, например: **com.company.app**.

Чтобы включить OneLink для обслуживания iOS и Android, важно определить одну и ту же схему для обеих платформ.

Когда в iOS 12.3.1 открыта `af_force_deeplink=true`, применяется следующая логика:

- Отображается диалоговое окно с запросом пользователя, установлено ли приложение:
  - Если пользователь выбирает OK (приложение установлено), AppsFlyer пытается открыть приложение с помощью схемы URI.
  - Если пользователь выбирает Отмена (приложение не установлено), AppsFlyer перенаправляет пользователя в магазин приложений.
  - Если пользователь выбрал ОК, но приложение не установлено, показывается сообщение об ошибке:
